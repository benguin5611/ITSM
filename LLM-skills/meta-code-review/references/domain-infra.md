# Domain overlay — Infrastructure

Load this file when the changeset contains `*.tf`, `*.tfvars`, `docker-compose*.yml`, `Dockerfile*`, or `.github/workflows/*.yml`. Extends the generic composition map with infrastructure-specific lenses, anti-patterns, and ROI gates.

## Lens additions
| Scope | Lens | Run via |
|---|---|---|
| Terraform plan correctness | `terraform plan` output — **required before any findings; no plan = no findings** | interactive — mandatory |
| IAM least-privilege | manual policy audit + `tfsec` / `checkov` | interactive |
| Secrets in plaintext | `trufflehog` / `gitleaks` scan | interactive |
| Contract changes touching a published API spec | breaking-change linter + spec diff | interactive — shared-type risk applies even to internal-only services |
| CI pipeline security | manual workflow audit | interactive |

## ROI gates
- No findings without a `terraform plan` output — findings without a plan are speculation.
- Skip auto-generated Terraform provider schemas (`*.tf.json` auto-generated by provider).
- Skip identity-provider auto-exported config — only hand-authored config is in scope.
- Skip Docker Compose service ordering already covered by `depends_on` in the file.

## Anti-patterns

**IN-G1. Secrets in plaintext in Terraform or scripts**
**Failure:** API keys, passwords, or tokens as `default` values in `variable` blocks, in `locals`, or hardcoded in resource arguments are exposed in the state file, version history, and CI logs.
**Check:** any secret value must come from a Secrets Manager / SSM Parameter Store data source or a CI secret injection mechanism. No literal credential strings in `.tf` or script files.

**IN-G2. Wildcard IAM actions or resources**
**Failure:** `Action: "*"` or `Resource: "*"` violates least-privilege and gives an attacker full control if the role is compromised.
**Check:** every IAM policy must specify the minimum necessary actions scoped to the minimum necessary resources. `*` in either field requires explicit justification; absent justification it is a defect.

**IN-G3. Missing `prevent_destroy` on critical persistent resources**
**Failure:** a `terraform destroy` or resource replacement silently drops databases, KMS keys, or primary object stores.
**Check:** every resource in the "never accidentally delete" category (databases, KMS keys, primary object storage) must have `lifecycle { prevent_destroy = true }`. A `terraform plan` proposing to destroy one of these without an explicit override is an automatic stop.

**IN-G4. Unpinned provider or module versions**
**Failure:** a `>=` constraint or absent `version` in `required_providers` allows breaking provider updates to land silently on `terraform init -upgrade`.
**Check:** every provider must use a `~>` (pessimistic constraint) or exact pin. Every external module must pin a version.

**IN-G5. Terraform state in local backend**
**Failure:** local state is not shared, not backed up, and has no locking. Concurrent `terraform apply` corrupts it.
**Check:** every Terraform root module must configure a remote backend with locking. A `terraform.tfstate` committed to the repo is always wrong.

**IN-G6. `count = 0` instead of `for_each` for conditional resources**
**Failure:** `count`-indexed resources are addressed by index; a count change destroys and recreates the resource. `for_each` addresses by key and handles conditional presence without replacement.
**Check:** conditional resources must use `for_each = var.enable ? toset(["x"]) : toset([])`, not `count = var.enable ? 1 : 0`.

**IN-G7. Missing encryption at rest or in transit**
**Failure:** data stored without encryption is exposed on disk compromise; data in transit without TLS is exposed to interception.
**Check:** every storage resource must have encryption at rest enabled. Every service-to-service path must enforce TLS. Explicit `encrypted = false` or unset encryption on a storage resource is a defect.

**IN-G8. Missing `depends_on` for implicit Terraform dependencies**
**Failure:** resources with a logical dependency not expressed by reference are created in parallel and fail intermittently on `apply`.
**Check:** when resource B cannot function until resource A exists but B does not reference A's attributes, add `depends_on = [resource.A]`.

**IN-G9. Docker images not pinned to digest**
**Failure:** a tag-only image reference resolves to whatever the registry returns on the day of pull; a registry update silently changes the running image.
**Check:** production and CI images must be pinned to `image: name:tag@sha256:<digest>`. Tag-only pins are acceptable only for ephemeral local dev.

**IN-G10. CI/CD pipeline with over-broad permissions**
**Failure:** a workflow with `permissions: write-all` or a broad implicit `GITHUB_TOKEN` scope can push to protected branches or publish packages if the workflow is compromised.
**Check:** every workflow must declare the minimum necessary `permissions` at the job level. A workflow that writes to the repo needs `contents: write`; everything else should be `read` or absent.

**IN-G11. No resource tagging strategy**
**Failure:** untagged cloud resources cannot be attributed to a team, cost centre, or environment; cost allocation and compliance audits are manual.
**Check:** every cloud resource must carry at minimum: `Environment`, `Team`, and `Project` tags. A resource without all three is incomplete.

**IN-G12. Stateful resources without backup or DR configuration**
**Failure:** a database, object store, or key store without a backup schedule has no recovery path for data loss.
**Check:** every stateful resource must have a backup schedule configured. The absence of a backup configuration is a defect.

**IN-G13. No Terraform plan gate in CI before apply**
**Failure:** a CI pipeline that runs `terraform apply` without a plan-and-review step can silently destroy or replace production resources.
**Check:** every CI pipeline applying Terraform must include a `terraform plan` step whose output is reviewed or gated on approval before `apply` runs. Auto-apply without a human-reviewed plan is only acceptable in dev environments.
